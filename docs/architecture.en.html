GRAPHIFY MCP PLATFORM

Platform architecture

Code, docs and files as knowledge-graph MCP servers — console, management, data, query and build planes, plus the Bedrock playground (ap-northeast-2)

SERVING

Query plane

  • One dedicated ECS Fargate service per repo (plus the all hub); the proxy routes to it through Cloud Map graphify.internal
  • Graphs hot-reload from S3 every 180s and on demand (os.replace); a source snapshot backs search_code/read_source
  • Auth: hashed API key plus a grant gate (DynamoDB, cache TTL 0) — private servers admit grant holders only

BUILD

Three build triggers

  • Poller (5-min tick, due-index) — watches git HEAD, upload hashes and crawl intervals
  • Console rebuild — the platform Lambda calls StartBuild directly
  • GitHub webhook push (omitted from the diagram) · on completion, EventBridge → completion Lambda records the status (omitted)

MODELS

Playground models

  • Four Bedrock cross-region inference profiles: claude-sonnet-4-6, claude-opus-4-6-v1, claude-opus-4-7, claude-opus-4-8
  • The Claude 5 family (Fable, Sonnet, Opus 5) is excluded — data-retention governance (provider_data_share) is not approved
  • The tool loop is client-driven (tunable, 1–30 rounds) — it calls the same data-plane REST API with X-Graphify-Key
